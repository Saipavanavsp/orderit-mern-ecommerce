## Conventions

**Response envelope**

```json
{ "success": true, "message": "optional", "data": { }, "meta": { "page": 1, "limit": 12, "total": 240, "pages": 20 } }
```

**Errors** (centralised handler; never includes stack traces in production)

```json
{ "success": false, "message": "Validation failed", "errors": [{ "field": "email", "message": "Enter a valid email address", "location": "body" }] }
```

| Status | Meaning |
|---|---|
| 400 | Validation failed (Zod), bad id, business rule (e.g. coupon not applicable) |
| 401 | Not logged in / session expired |
| 403 | Logged in but not allowed (role), or account deactivated |
| 404 | Resource or route not found |
| 409 | Duplicate (email, review) or stock conflict at checkout |
| 413 | Body too large |
| 423 | Account locked after repeated failed logins |
| 429 | Rate limit exceeded |
| 502 | Payment gateway / upload provider error |

**Authentication.** `POST /auth/login` sets two HTTP-only cookies: `oi_access` (JWT, 15 min) and `oi_refresh` (JWT, 7 days, path `/api/v1/auth`, rotated on every refresh and stored hashed in the database; replaying an old refresh token revokes all sessions). Browsers send them automatically with `withCredentials: true`. The admin dashboard sends `X-Client-App: admin` and receives separately named cookies (`oi_admin_access`, `oi_admin_refresh`); customer accounts are refused there. API clients may instead send `Authorization: Bearer <access token>`.

**Rate limits** (per IP): general API 1000 / 15 min · login 10 / 15 min · register 10 / hour · forgot/reset password 5 / 15 min · payments 30 / 15 min · AI chat 20 / min.

**Security middleware**: Helmet headers, CORS allow-list (`CORS_ORIGINS`), `express-mongo-sanitize` (strips `$`/`.` operators), XSS filtering of every string input (passwords and tokens excluded), 1 MB JSON limit, Zod validation on every body/query/params, upload MIME + magic-byte + size checks, Razorpay HMAC-SHA256 signature verification with timing-safe comparison.

**Pagination & sorting.** List endpoints accept `page` (default 1) and `limit`. `GET /products` sorts by `relevance | popularity | price_asc | price_desc | rating | newest | discount`.

## Example: checkout with payment (simulation mode)

```text
POST /auth/login                      {"email":"aarav.sharma@example.com","password":"Customer@123"}
POST /cart/items                      {"productId":"<id>","quantity":1}
POST /cart/coupon                     {"code":"WELCOME10"}
POST /orders                          {"paymentMethod":"razorpay","addressId":"<saved address id>"}
POST /payments/create-order           {"orderId":"<order id>"}          -> providerOrderId
POST /payments/simulate               {"orderId":"…","providerOrderId":"…","outcome":"success"}  -> signed result
PUT  /orders/<order id>/pay           {"razorpayOrderId":"…","razorpayPaymentId":"…","razorpaySignature":"…"}
```

With Razorpay test keys configured, step 6 is replaced by the Razorpay Checkout widget, which returns the same three fields.

### Auth

| Method | Path | Access | Description |
|---|---|---|---|
| `POST` | `/auth/register` | Public | Register a customer account (sets auth cookies) (JSON body) |

| `POST` | `/auth/forgot-password` | Public | E-mail a password reset link (always 200) (JSON body) |
| `POST` | `/auth/reset-password/{token}` | Public | Reset password with the e-mailed token (JSON body) |
| `PUT` | `/auth/change-password` | Logged in | Change password (signs out other sessions) (JSON body) |
